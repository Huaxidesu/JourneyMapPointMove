# JourneyMapPointMove

> 状态：**v1.1.0，功能已实现，53 项自测通过**（2026-11-10）。
> v1.1.0 起默认交互改为「打开 → 按回车 → 完成」，复杂功能收进高级选项。

解决 Minecraft 1.7.10 / JourneyMap 5.2.x 的一个问题：同一台服务器有多条线路时，
JourneyMap 按「线路标识 + 世界 UUID」分别建立数据目录，玩家换线路进服后看不到原先的标点。
本工具扫描本机全部线路目录，把同一世界的标点补齐到每一条线路。

## 背景

JourneyMap 5.2.23 的多人数据位于 `journeymap/data/mp/<线路标识>_<世界UUID>/waypoints/`。
实测同一个世界可以对应三条线路目录，而标点只保存在其中一条；改用另外两条线路进服时标点为空。
世界 UUID 由服务端经 `world_info` 通道下发，是判断两条线路是否属于同一世界的唯一可靠依据。
数据格式与搬运规则见本地开发文档，不随仓库分发。

## 功能

- **一键同步**：打开工具直接按回车，自动把标点补齐到同世界的每条线路，不覆盖已有标点。
- **首次自动找目录**：在常见游戏位置搜索 `journeymap` 目录，按最近使用时间推荐；
  找不到时把文件夹拖进窗口即可，路径写入 `config.json`，以后不再询问。
- **一键撤销**：主界面 `[1]` 还原到最近一次同步前；每次同步前自动备份。
- **高级选项**：手动选线路、四种模式（A 单线 / B 合并 / C 全线路同步 / D 实时共享）、
  三种冲突策略、备份导出与按时间点回滚，保留给需要精细控制的用户。
- 只处理 `waypoints/*.json`，不改动地图瓦片 `DIM*` 目录。
- 命令行 `--one-click --yes` 可做成桌面快捷方式，无提示完成同步。

## 运行形态

Windows 平台。入口为 `旅行地图标点搬运.bat`（内容保持纯 ASCII），调用随包内置的
Python 3.13.1 embeddable 运行时；玩家无需自行安装 Python。运行时本身不入库，
由 `tools/build_dist.py` 在生成发布包时下载并组装，交付格式为 zip。

## 目录结构

```
JourneyMapPointMove/
├── 旅行地图标点搬运.bat       入口（内容纯 ASCII）
├── 使用说明.md                玩家文档
├── python/                    内置 Python 运行时，发布包内提供，不入库
├── app/                       Python 源码
├── tools/                     夹具、自测与发布包组装脚本
├── config.json                首次运行生成，不入库
├── backup/                    自动备份，不入库
├── shared/                    目录联接共享数据，不入库
└── tmp/                       测试夹具，不入库
```

## 快速开始

1. 双击 `旅行地图标点搬运.bat`；开发时也可运行 `python -m app.main`。
2. 首次使用确认工具找到的游戏目录（或把目录拖进窗口），之后不再询问。
3. 主界面**直接按回车**，看到「完成！」后重新进入游戏。

详细步骤见 [`使用说明.md`](使用说明.md)。
